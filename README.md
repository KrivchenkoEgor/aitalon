# AITalon — талон на чат

Тестовый проект: человек получает талон (QR-код или код на листке), открывает ссылку,
попадает сразу в чат и выбирает, у какой модели спросить. Ничего набирать не надо —
адрес и код талона уже зашиты в QR.

## Что откуда берётся

| Путь | Зачем |
|---|---|
| `app/main.py` | HTTP-сервер: вход по талону, чат, операторская |
| `app/tickets.py` | документы и талоны: выпуск, привязка к устройству, срок, досрочное закрытие |
| `app/db.py` | база (SQLite): талоны, расход по каждому |
| `app/gate.py` | подпись и проверка cookie сессии |
| `app/sources.py` | выбор источника ответа и учёт расхода |
| `app/zro.py` | два источника через API: `deepseek-v4.1-flash`, `glm-5.3-flash` |
| `app/qwen_browser.py` | третий источник `qwen` — через браузер, плюс чистка чатов |
| `app/sheet.py` | лист A4 с QR-кодами (по 10 на страницу) и печать в PDF |
| `app/web/` | страница чата и операторская |
| `qwwen/qwen.py` | разметка и шаги сайта Qwen: вход, чат, отправка вопроса, чтение ответа |
| `checks/check.py` | проверки боевым HTTP, одним скриптом без фреймворка |

## Установка

Нужен Python 3.13 (в `PATH` обычно лежит 3.8 без FastAPI):

```sh
/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 -m pip install -r requirements.txt
cp .env.example .env   # и заполнить: AITALON_ADMIN_KEY, ZRO_API_KEY
```

Для браузера нужен обычный Google Chrome: команда `playwright install` не запускается,
потому что встроенный Chromium этой сборке Python не подходит, а движок поднимает
установленный Chrome (`channel="chrome"`).

## Запуск

```sh
./run.sh                      # слушает 0.0.0.0:8000 — чтобы открыть чат с телефона по QR
AITALON_HOST=127.0.0.1 ./run.sh   # только на этой машине
```

Страница чата — `http://<адрес>:8000/`, операторская — `/admin`.

## Первый запуск на новом компьютере

1. Python 3.13: `/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 --version`
   на Mac; на другой машине — любой интерпретатор 3.13, просто подставьте его путь в
   команды ниже. На 3.8 приложение не поднимется (там нет FastAPI).
2. Зависимости: `-m pip install -r requirements.txt`.
3. Google Chrome должен быть установлен — на нём работают и печать PDF, и третий
   источник (см. «Третий источник — браузер»).
4. `cp .env.example .env` и заполнить `AITALON_ADMIN_KEY` (свой ключ операторской) и
   `ZRO_API_KEY` (доступ к zro.moonmath.ai). Для Qwen — см. ниже.
5. `./run.sh`, затем открыть `http://localhost:8000/admin` и посмотреть строку
   «в QR-код зашит адрес: …». Это тот адрес, который попадёт в QR-коды талонов.
6. Проверить, что всё собрано: `python3.13 checks/check.py` (браузер не запускается,
   настоящая база не трогается).

Телефон должен быть в той же сети, что и компьютер: `./run.sh` слушает `0.0.0.0`.
Режим `AITALON_HOST=127.0.0.1 ./run.sh` оставляет доступ только с этой машины — тогда
QR-коды работать не будут.

**Что происходит, если шаг пропущен** (проверено на копии репозитория без `.env`):

| Чего нет | Что вы увидите |
|---|---|
| `AITALON_ADMIN_KEY` | операторская отвечает «Операторская закрыта: задайте AITALON_ADMIN_KEY в .env» |
| `ZRO_API_KEY` | чат отвечает «Ответ не пришёл: Не задан ZRO_API_KEY — положи его в .env» |
| доступа к Qwen | вопрос третьему источнику через полминуты даёт «Сессия Qwen не живая, а QWEN_EMAIL/QWEN_PASSWORD не найдены — нужно одно из двух: рабочая сессия в профиле или креды в .env» |
| Chrome | страница чата и выдача талонов работают, но печать PDF и источник Qwen не запускаются |

Адрес для QR по умолчанию строится на машине оператора: берётся её mDNS-имя
(`что-то.local`), а если такой системы нет (Linux, Windows) — её сетевой адрес.
Значение можно задать явно: `AITALON_BASE_URL=http://192.168.1.55:8000`. Имя живёт
дольше (роутер может выдать другой IP, а отпечатанные листки останутся верны), IP
точнее, но протухает; в гостевых сетях mDNS иногда режут — там тоже помогает явный
`AITALON_BASE_URL`.

## Операторская

Вход по `AITALON_ADMIN_KEY`. Документ выпускается одним движком: количество талонов,
век талона (считается от первого входа), век всех талонов документа (от создания).
Документ печатается листом A4 или PDF, каждый талон — своим QR.

«Закрыть» гасит документ целиком: по уже активированным талонам вход тоже закрывается,
а их чаты на стороне Qwen удаляются фоном. В строке видно прогресс — «удаляем чаты: 1 из 2»,
потом итог «чаты удалены · чатов не было · не удалены». Удаляются только те чаты, чей id
лежит в привязках `qwwen/chats.json` под именем `aitalon-<талон>`: чужие чаты не трогаются,
а статус «удалён» ставится только когда повторный заход по адресу чата его не открыл.

## Третий источник — браузер

Он берёт ответы не по API, а через сайт Qwen: один Chrome, отдельная вкладка на каждый
талон, все активные талоны опрашиваются за один шаг цикла.

Под какой учётной записью он работает — решает тот, кто запустил сервер. На новом
компьютере для этого достаточно положить в `.env` `QWEN_EMAIL` и `QWEN_PASSWORD` своей
учётной записи: сервер войдёт сам, а cookies останутся в папке `qwwen/profile/` на этом
же диске. Профиль, сессия и привязки чатов в git не попадают — в репозитории из `qwwen/`
лежит один файл `qwen.py` с шагами сайта. Чужую учётную запись в `.env` вписывать не
зачем и небезопасно: источник будет работать под той, что ваша.

Ответы всех талонов приходят в один аккаунт, поэтому в его сайдбаре видны первые вопросы
всех талонов. Из-за этого окно по умолчанию скрыто; `QWEN_WINDOW=1` показывает его —
например, когда Qwen задал проверку человеку. Закрытие документа в операторской удаляет
его чаты на стороне Qwen (см. выше), а если окно всё же на экране, оно не перекрывает
работу оператора.

## Проверки

```sh
/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 checks/check.py
```

Скрипт поднимает приложение боевым HTTP-клиентом (отдельная база во временной папке) и
проверяет правила талонов, учёт расхода, страницу, операторскую, печать PDF, разбор
разметки Qwen и логику наблюдения ответа. В конце — «ВСЁ ЗЕЛЁНОЕ» или список падений.
Проверки не запускают браузер и не трогают настоящую базу.

## Чего в репозитории нет намеренно

`.env` с ключами, профиль браузера с сессией Qwen, база с выданными талонами и расходом,
привязки чатов, дампы страниц и логи. Всё это создаётся на машине, где проект запущен.
