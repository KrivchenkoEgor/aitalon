# AITalon — талон на чат

Тестовый проект: человек получает талон (QR-код или код на листке), открывает ссылку,
попадает сразу в чат и выбирает, у какой модели спросить. Ничего набирать не надо —
адрес и код талона уже зашиты в QR.

## Что откуда берётся

| Путь | Зачем |
|---|---|
| `app/main.py` | HTTP-сервер: вход по талону, чат, операторская |
| `app/tickets.py` | документы и талоны: выпуск, привязка к устройству, срок, досрочное закрытие |
| `app/db.py` | база (SQLite): талоны, расход по каждому |
| `app/gate.py` | подпись и проверка cookie сессии |
| `app/sources.py` | выбор источника ответа и учёт расхода |
| `app/zro.py` | два источника через API: `deepseek-v4.1-flash`, `glm-5.3-flash` |
| `app/qwen_browser.py` | третий источник `qwen` — через браузер, плюс чистка чатов |
| `app/sheet.py` | лист A4 с QR-кодами (по 10 на страницу) и печать в PDF |
| `app/web/` | страница чата и операторская |
| `qwwen/qwen.py` | разметка и шаги сайта Qwen: вход, чат, отправка вопроса, чтение ответа |
| `checks/check.py` | проверки боевым HTTP, одним скриптом без фреймворка |

## Установка

Нужен Python 3.13 (в `PATH` обычно лежит 3.8 без FastAPI):

```sh
/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 -m pip install -r requirements.txt
cp .env.example .env   # и заполнить: AITALON_ADMIN_KEY, ZRO_API_KEY
```

Для браузера нужен обычный Google Chrome (встроенный Chromium этой сборке Python не
подходит). Ставится он как всегда с этим пакетом, поэтому отдельной команды нет.

## Запуск

```sh
./run.sh                      # слушает 0.0.0.0:8000 — чтобы открыть чат с телефона по QR
AITALON_HOST=127.0.0.1 ./run.sh   # только на этой машине
```

Страница чата — `http://<адрес>:8000/`, операторская — `/admin`.
Адрес, который зашивается в QR, по умолчанию строится по имени машины в локальной сети
(`MacBook.local`), поэтому листки не протухают, когда роутер выдаст другой IP. В гостевых
сетях mDNS иногда режут — тогда задайте `AITALON_BASE_URL` явно.

## Операторская

Вход по `AITALON_ADMIN_KEY`. Документ выпускаетесь одним движком: количество талонов,
век талона (считается от первого входа), век всех талонов документа (от создания).
Документ печатается листом A4 или PDF, каждый талон — своим QR.

«Закрыть» гасит документ целиком: уже активированные талоны тоже перестают пускать, а
их чаты на стороне Qwen удаляются фоном. В строке видно прогресс — «удаляем чаты: 1 из 2»,
потом итог «чаты удалены · чатов не было · не удалены». Удаляются только те чаты, чей id
лежит в привязках `qwwen/chats.json` под именем `aitalon-<талон>`: чужие чаты не трогаются,
а статус «удалён» ставится только когда повторный заход по адресу чата его не открыл.

## Третий источник — браузер

У Qwen нет публичного API под этот аккаунт, поэтому ответы приходят через настоящий
браузер: один Chrome, отдельная вкладка на каждый талон, все активные талоны опрашиваются
за один шаг цикла. Профиль и cookies живут в `qwwen/profile/` (в git не попадает). Если
сессия в профиле не живая, берётся `QWEN_EMAIL` / `QWEN_PASSWORD` — и только они.

По умолчанию окно скрыто; `QWEN_WINDOW=1` показывает его (например, когда Qwen задал
проверку человеку). Скрытым окно держится потому, что в сайдбаре одного аккаунта видны
первые вопросы всех талонов.

## Проверки

```sh
/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 checks/check.py
```

Скрипт поднимает приложение боевым HTTP-клиентом (отдельная база во временной папке) и
проверяет правила талонов, учёт расхода, страницу, операторскую, печать PDF, разбор
разметки Qwen и логику наблюдения ответа. В конце — «ВСЁ ЗЕЛЁНОЕ» или список падений.
Проверки не запускают браузер и не трогают настоящую базу.

## Чего в репозитории нет намеренно

`.env` с ключами, профиль браузера с сессией Qwen, база с выданными талонами и расходом,
привязки чатов, дампы страниц и логи. Всё это создаётся на машине, где проект запущен.
